04Lessons

What the three stages taught us.

01

A queue protects data, not time

MQTT lost nothing where HTTP lost about a third at 500 msg/s, but storing a 120 s burst took about 285 s on Stage B and about 560 s with one worker on Stage C. No loss is not real time.

02

The small VM ran out of CPU first

The t3.small was about 85% busy during HTTP at 500 msg/s and dropped 56,487 readings. Memory, swap and CPU credits were fine.

03

Managed services move the limits

With RDS each save is two network round trips, so server time went from 2.3–3.0 ms to 4.3–4.8 ms and one worker stores only about 104/s. SQS lets workers share the queue: 4 workers reached 372/s (3.6×). RDS db.t4g.micro allows 79 connections, so pools must fit.

04

Moving the database is quick, but not free

A cold cutover of 1,000,000 rows to RDS stopped storing for about 15 s with MQTT (0 lost) and about 25 s with HTTP (about 2,500 lost per run). Dump and restore took only about 4 s and 8–10 s.

05

Cheap to test, IoT Core is the bill

Stage B's test window cost about $0.09. Stage C's 21 runs cost about $0.98 for 633,600 messages, $1.55 per million, and 88% of it was IoT Core (Mumbai list prices, before credits).
